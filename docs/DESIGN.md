# 要件と設計

> この文書は学校提出版v0.3.3の記録です。現行版の追加機能は[更新内容と検証範囲](RELEASE-v0.4.0.md)を参照してください。

## 課題
録画で容量がいっぱいになった際に、整理候補をおすすめしてほしい。

## 必要な機能への落とし込み
容量を把握する一覧、候補の理由、残す・保留の判断、確認を挟む整理リスト保存を実装する。日常でも使いやすいよう、インストール不要のWeb版とスマホ向け動画選択を用意した。

## 基本設計
静的HTML/CSS/JavaScriptで構成し、選択されたファイルの情報をブラウザ内で扱う。サーバーは静的配信のみ。認証や動画アップロードを必須にしない。候補を自動削除せず、ユーザーが根拠を確認して判断する。

## 詳細設計
- ファイル情報：ID、名前、パス、容量、最終更新日時、File参照。
- 候補理由：core.mjsのreasonsで古さ・容量・0バイトを個別に評価し、理由の配列を返す。
- 判断：パス・容量・最終更新日時をJSON化したキーにkeep/laterを対応付ける。noneは未整理。
- 状態：読み込み一覧・選択集合はメモリ、実ファイルの判断だけlocalStorage。サンプル判断はメモリのみ。
- 一括選択：検索・一覧条件に合う候補を全ページから選び直し、keepを除外。表示は50件単位。
- 出力：確認後にUTF-8 BOM付きCSVを生成。セルの引用と数式として扱われる文字への対処を行う。
- 動画プレビュー：File参照から端末内のBlob URLを作成。対応形式はブラウザに依存する。
