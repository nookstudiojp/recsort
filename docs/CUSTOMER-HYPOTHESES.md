# 顧客像と悩みの仮説・確認計画

2026年11月9日。当日発表資料の補足です。**体系的な顧客ヒアリングは未実施です。** 以下の顧客像・場面・効果は検証前の仮説です。

## 出発点と、確認できた情報

学校の「録画で容量がいっぱいなので、削除をおすすめしてほしい」という課題から開発しました。課題提供者からは、スマホに約1,700件の動画があること、保留にしても再び迷いそうなことなど、質問・感想をいただきました。

これは利用場面・整理頻度・現在の対処方法まで把握した顧客調査ではありません。容量不足の具体的な場面、撮影用途、削除に迷う理由、圧縮や外部保存を使う条件は未確認です。

## 最初に確かめたい利用者像

スマホに動画をため、容量不足でも整理を先延ばしにする人を想定しています。次の撮影や保存に備えて容量を空けたいが、大切な動画まで消しそうで迷う、という利用場面の仮説です。課題提供者が必ずこの場面で困っている、と断定するものではありません。

## 悩みと機能の対応

| 悩みの仮説 | 役立てたい機能 | 利用者と確かめること |
| --- | --- | --- |
| 何が容量を使うか分からない | 容量順の一覧、理由付き候補 | 見直す動画を探しやすいか |
| 大切な動画を消すのが不安 | 「残す」の保護、最後の確認 | 安心して判断できるか、確認が負担にならないか |
| 残したいが容量も減らしたい | 元動画を残す圧縮コピー（開発版・iOS試作） | 画質と容量の両立が必要か、コピー確認・元動画整理ができるか |
| 一度に多く判断すると疲れる | 「今日の5本」などの少量選択 | 必要な補助機能か、5本という数が適切か |

機能の実装と、顧客の悩みを解決できたことは区別します。コピー保存直後は容量が増え、保存だけでは空き容量は増えません。公開Web版と公開前の開発機能は[提供状況](../README.md#versions)を参照してください。

## 次に行う確認（未実施）

まず容量不足で困る本人と直接話し、自由に答えてもらいます。機能を提案する前に、具体的な直近の行動を聞く方針です。

1. 最近、容量不足で困ったのはいつ、何をしようとしたときか。
2. どんな動画が多く、何を残したいか。消せない理由は何か。
3. 今はどう対処しているか。圧縮・クラウド・PC保存を使う、使わない理由は何か。
4. 整理にかかる時間や、繰り返し困る操作は何か。
5. 本人の同意のもとでプロトタイプを使ってもらい、迷った箇所・所要時間・誤選択を確認する。
6. 使い続けたい場面と条件を聞き、必要な機能を絞る。料金や支払い意思も、具体的な価値を確認してから検討する。

動画の内容や私的なデータを見せることを必須にしません。回答や調査実績を創作せず、確認できた事実に応じて顧客像と機能を見直します。
